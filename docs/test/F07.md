# Kiểm thử UI F07 — Lưu Draft Data Dictionary

## Điều kiện chuẩn bị

| Đối tượng | Điều kiện |
| --- | --- |
| Manager | `canViewWorking=true`, `canEditWorking=true` |
| Viewer | `canViewWorking=true`, `canEditWorking=false` |
| Consumer-only | `canViewPublished=true`, `canViewWorking=false` |
| Dữ liệu | Môi trường sạch đã bootstrap Data Dictionary Draft v1.0 |
| Công cụ | Mở DevTools → Network để kiểm tra request và response |

## Kịch bản kiểm thử cốt lõi

| Mã | Kịch bản | Các bước thực hiện | Kết quả mong đợi |
| --- | --- | --- | --- |
| F07-UI-01 | Mở Draft đã bootstrap | Đăng nhập Manager và mở `/glossary/Data%20Dictionary`. | Hiển thị “Từ điển dữ liệu dùng chung”, badge `Draft`, business version `1.0`; gọi `GET /permissions` rồi `GET /working`; không có nút hoặc form tạo Data Dictionary. |
| F07-UI-02 | Không còn luồng tạo Data Dictionary | Kiểm tra sidebar, empty state và truy cập trực tiếp `/glossary/add`. | Không hiển thị nút/form tạo; route cũ chuyển về Data Dictionary; không phát sinh `POST /api/v1/glossaries`. |
| F07-UI-03 | Phân quyền xem và sửa | Lần lượt đăng nhập Manager, Viewer và Consumer-only rồi mở Data Dictionary. | Manager xem và sửa được Draft; Viewer xem nhưng không lưu được; Consumer-only không thấy Draft và không nhận working payload. |
| F07-UI-04 | Lưu Draft thành công | Manager sửa description, owners, reviewers, domains, tags hoặc custom properties rồi nhấn “Lưu nháp”. | Chỉ gửi một `PATCH /glossaries/{id}/working`; nút bị disable/loading trong lúc lưu; request chỉ chứa `expectedRevision` và sáu field mutable; response thay toàn bộ state; `businessVersion` vẫn `1.0`; revision tăng đúng một. |
| F07-UI-05 | Lưu nhiều lần và reload | Lưu hai lần liên tiếp, sau đó nhấn F5. | Revision tăng tuần tự `1 → 2 → 3`; mỗi request dùng revision mới nhất; nội dung đã lưu còn nguyên sau reload; không tạo business version mới. |
| F07-UI-06 | Chặn double-submit | Bật Network throttling, thay đổi dữ liệu rồi double-click “Lưu nháp”. | Chỉ có một PATCH; action bị disable khi request đang chạy; revision chỉ tăng một. |
| F07-UI-07 | Conflict giữa hai tab | Mở cùng Draft ở hai tab; tab A lưu trước; tab B lưu bằng revision cũ. | Tab B nhận `409`; không tự retry hoặc đóng form; dữ liệu chưa lưu được giữ lại; có cảnh báo và lựa chọn tải bản mới nhất, kèm xác nhận trước khi thay thế dữ liệu hiện tại. |
| F07-UI-08 | Validation và field bị khóa | Thử nhập reference/custom property không hợp lệ; kiểm tra các field identity, version, status và `termRevisions`. | Validation thất bại không làm tăng revision; form giữ dữ liệu; các field server-owned và `termRevisions` không thể chỉnh sửa hoặc gửi trong PATCH. |
| F07-UI-09 | Trạng thái không được sửa | Mở fixture Data Dictionary ở trạng thái `InReview`, sau đó `Rejected`. | Form chỉ đọc, không có “Lưu nháp”; nếu ép PATCH thì backend từ chối; payload và revision không đổi. |
| F07-UI-10 | Restart giữ nguyên Draft | Lưu Draft, ghi lại nội dung/revision, restart hoặc tạo lại server container nhưng giữ PostgreSQL volume, rồi reload UI. | Vẫn đúng một Data Dictionary; nội dung/revision mới nhất không đổi; restart không tăng revision, không tạo snapshot hoặc published version. |

## Payload PATCH cần kiểm tra

```json
{
  "expectedRevision": 1,
  "payload": {
    "description": "Mô tả mới",
    "owners": [],
    "reviewers": [],
    "domains": [],
    "tags": [],
    "extension": null
  }
}
```

Payload không được chứa `id`, `name`, `displayName`, `fullyQualifiedName`, `versioningMode`, `businessVersion`, `workingRevision`, `entityStatus`, native `version`, `termRevisions`, publication metadata hoặc audit metadata.
